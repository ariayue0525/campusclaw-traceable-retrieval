## Context

第 3 课的信任边界保持不变：浏览器只访问 Nginx，Go 是唯一执行认证、授权、班级过滤与文件校验的地方，MySQL 与上传目录不直接暴露。本课在这条链路上追加四个服务端模块——切分、嵌入、向量库、对话——并把它们编排进检索模块。

新增的两个外部依赖只接受 Go 发起的调用：Qdrant 存放浮点向量，课程网关提供 OpenAI 兼容的 `/embeddings` 与 `/chat/completions`。二者的密钥都留在服务端环境变量里，不下发到页面，页面上也从不展示向量分量。

## Goals / Non-Goals

Goals：把正文切成可定位的切片并嵌入入库；以关键字、向量、混合三种模式在本班范围内检索；每条命中可回溯到材料、切片序号与字符区间；无依据时明确返回未找到且不调用生成模型；全部过滤发生在服务端。

Non-goals 见 proposal。

## Decisions

### D1 两库分工与关联方式

切片正文只存 MySQL `knowledge_chunks.chunk_text`；Qdrant 只保存定长浮点向量与 payload 标识（`class_id`、`material_id`、`knowledge_entry_id`、`chunk_id`、`chunk_index`），不含任何正文字符串。向量主键、 `knowledge_chunks.id` 与 `payload.chunk_id` 三者相同，检索时先命中向量记录，再用同一主键回 MySQL 取回正文。

理由：摘录取自 MySQL，关键字检索与结果展示都不依赖 Qdrant；Qdrant 不可用时关键字路径仍可独立降级。主键一致即可直接回表，不需要在向量库里再存一份字符串副本。

### D2 三种检索模式各自访问哪些组件

| 模式 | 访问的组件 | 排序与过滤 |
|---|---|---|
| keyword | 仅 MySQL 全文索引（`FULLTEXT ... WITH PARSER ngram`，token 长度 2） | 按全文相关度降序；`class_id = 会话班级` 且 `index_status = 'ready'` |
| vector | 先调嵌入网关把问句转成向量，再查 Qdrant（带 `class_id` 过滤），余弦低于阈值（网关嵌入 0.35、本地哈希嵌入 0.15）丢弃，最后回 MySQL 取正文 | 按余弦相似度降序；回表 SQL 再带一次同班条件 |
| hybrid | 两条路径都执行 | 各路先按绝对分数独立过滤，再按名次执行 RRF（k = 60）；缺席的一路不贡献分数 |

混合模式融合的是**名次**而不是分数：全文相关度与余弦相似度的量纲不同，直接相加没有意义，更换嵌入模型也不需要重新标定权重。

### D3 班级标识只来自会话，两条路径都要过滤

认证中间件已把 `user.class_id` 写进请求上下文。检索模块只从上下文读班级；查询字符串、JSON 正文、请求头中出现的班级编号在解析后一律丢弃。

只在单侧过滤并不充分：若 Qdrant 漏了过滤条件，回表时的 `class_id` 约束仍要把他班记录排除；反之若 MySQL 漏了，Qdrant 过滤也在。因此两条路径**都**显式携带会话班级，且回表再次核对。

跨班级检索对外表现为「无命中」：HTTP 200 且 `hits` 为空（或 `status = "no_evidence"`），不返回 403/404，避免泄露「该资料属于其他班级」这一存在性信息。按材料标识打开详情仍沿用第 3 课规则，跨班与不存在都是 404。

### D4 先检索，再生成；无命中不调用对话网关

`POST /api/ask` 自身不实现第三种检索。它先用混合模式取本班前 4 条切片：

- 一条都没有 → 直接返回固定文案「资料中未找到相关内容」，`citations` 为空，不调用对话网关，也不构造任何提示词；
- 有切片 → 把材料标题、切片序号、切片正文与用户最新一句提问交给对话模块，回答中以 `[1]`、`[2]` 指回出处，编号顺序与 `citations` 数组顺序一致。

对话模块拿不到向量分量，也拿不到其他班级的切片；客户端自行构造的 `system` 消息在解析时丢弃。这样即使模型想凭参数记忆回答天气、比分一类问题，也没有入口。

### D5 切分策略与预处理的作用范围

三种策略作用于同一份 `body_text`：

- `auto`：最大 800 字、重叠 80 字，优先在空行、换行、句号处断开；请求中另行填写的长度与预处理参数不生效；
- `custom`：最大长度 100–2000 字，重叠比例 0%–50%，分隔符可选换行 / 空行 / 句号，可选移除 URL 与邮箱、把连续空白折叠为单个空格；无断点处按最大长度强制截断；
- `hierarchy`：按 `#` / `##` / `###` 分章，标题保留在该章切片内，超长章节再按 `auto` 规则切分。

未指定策略时按 `auto` 处理。预处理只作用于**待切分与待嵌入的文本**，不改写 `knowledge_entries.body_text`；因此切片偏移量是相对于预处理后文本计算的，不能当作原文件下标。种子材料启动时补齐索引同样采用 `auto`。

### D6 重建索引先删后写，失败保留原文

已入库材料不会自动重新切分；切换策略必须显式重建索引。重建时先删除旧切片行与旧向量记录（按 `chunk_id` 列表删除 Qdrant 点），再按本次请求策略重新切分、嵌入、写入，避免遗留过期主键。

嵌入失败时材料记录与已写入的切片行仍然保留，只是这些切片的 `index_status` 标记为 `failed`，不写入不完整的向量数据；`ready` 之外的切片不参与检索。材料模块先保留原文，检索模块失败时原文仍可下载浏览。

### D7 Qdrant 不可用时的降级语义

关键字检索不依赖 Qdrant，Qdrant 故障时应正常返回结果。向量与混合模式无法给出相似度，返回 503，不编造相似度分数也不伪造命中。空查询、仅空白的查询返回 400。

### D8 嵌入实现可替换，默认不依赖外部密钥

嵌入模块抽象为接口：配置 `EMBED_PROVIDER=gateway` 时调用课程网关的 OpenAI 兼容 `/embeddings`；未配置密钥时回退到内置的确定性本地嵌入器（字符 uni/bi-gram 哈希 + L2 归一化），保证仓库在没有任何密钥的情况下也能一键启动并演示三种模式。两种实现的维度必须与 Qdrant 集合的 `size` 一致，否则启动时以 503 明确失败而不是写入错误维度的点。

### D9 部署前缀

静态资源与接口都以 `/week04` 为前缀对外发布：Nginx 把 `/week04/` 映射到站点根，把 `/week04/api/` 反向代理到 Go 的 `/api/`，原 `/api/` 路径保留以便本地直连与既有脚本。前端 Vite `base` 设为 `/week04/`。

## Data model

新增 `knowledge_chunks`：

| 字段 | 说明 |
|---|---|
| `id` | 主键；等于 Qdrant 向量主键与 `payload.chunk_id` |
| `material_id` / `knowledge_entry_id` / `class_id` | 归属与班级边界 |
| `chunk_index` | 切片序号，从 0 开始 |
| `chunk_text` | 切片正文，建立 ngram 全文索引 |
| `start_offset` / `end_offset` | 相对**预处理后**文本的字符区间 |
| `index_status` | `pending` / `ready` / `failed`；只有 `ready` 参与检索 |
| `chunk_strategy` | 本次使用的切分策略 |

## API

| 方法与路径 | 鉴权 | 语义 |
|---|---|---|
| POST `/api/search` | 会话 | `{q, mode, limit, offset}` → `{mode, q, query_vector, hits[], status, message}` |
| POST `/api/ask` | 会话 | `{q, history[]}` → `{answer, status, citations[]}` |
| POST `/api/materials/{id}/reindex` | 会话+教师+班级 | 按请求策略重建切片与向量 |
| GET `/api/materials/{id}/vectors` | 会话+班级 | 切片与向量库的对照（主键、payload、维度、前若干分量） |
| POST `/api/materials` | 教师 | 上传成功后按请求中的切分参数建索引，响应带 `chunk_count`、`chunk_strategy` |

## Risks

- 本地回退嵌入器是词法相似而非语义相似，同义改写场景的召回弱于真实嵌入模型；配置网关密钥后即为真实语义检索。
- MySQL ngram 全文索引对短查询噪声较多，故关键字路径仍要求 `index_status = 'ready'` 并按相关度排序，不保证与向量路径同序。
- 单实例部署下嵌入与检索同步执行，大材料上传会有可见延迟；本课不做异步队列（第 8 课范围）。
