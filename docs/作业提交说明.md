## 2. 后端 API 是否暴露给用户？如何通过浏览器访问？

API 对浏览器“可用”，但 Go 容器端口不直接暴露到宿主机。唯一入口是 Nginx 的 `http://localhost:8080`：

- `/api/*` 由 Nginx 同源反向代理到 Go；
- `/health` 也由 Nginx 代理；
- MySQL 3306、Go 8081 和上传目录均不对用户直接开放；
- 在地址栏直接打开 GET API（例如 `/api/me`）可看到 JSON/401；POST 登录应用浏览器开发者工具或 curl，不能靠地址栏构造。

这种结构既满足浏览器访问，也把认证、授权、隔离和文件校验全部留在服务端信任边界内。

## 3. 文件下载是否需要权限？实现逻辑

需要。原文件没有配置成 Nginx `/uploads` 静态目录，只能请求：

`GET /api/materials/{id}/file`

Go API 依次执行：读取 HttpOnly Cookie → 查询服务端 session → 从用户表恢复实时角色和班级 → 读取材料 → 比较 `material.class_id` 与 `user.class_id` → 同班才打开随机存储名文件并返回 `Content-Disposition: attachment`。未登录返回 401，跨班或不存在统一返回 404，避免泄露 B 班材料是否存在。

## 4. 文件上传逻辑；支持哪些类型？

只支持 UTF-8 编码的 `.txt` 和 `.md`（扩展名不区分大小写），默认上限 2 MiB。`.pdf`、`.docx`、图片、可执行文件等均拒绝。

处理顺序：

1. 服务端会话鉴权；学生立即 403；
2. 限制 HTTP body 与文件大小；校验扩展名、UTF-8 和标题；
3. 生成随机存储名，写入上传卷的临时文件并 `fsync`；
4. 开启 MySQL 事务，写 `materials` 和 `knowledge_entries`；
5. 临时文件原子改名后提交事务；
6. 任一步失败均回滚两张表并删除临时/最终文件。

## 5. 用户登录成功以后，用户身份识别方式

登录后服务器生成 256-bit 随机 token，浏览器只保存 `campusclaw_session` Cookie（HttpOnly、SameSite=Lax）。数据库 `sessions` 表只保存 token 的带密钥 HMAC 后再 SHA-256 的摘要及用户 ID/过期时间。

每次请求都由服务器用 Cookie 查 session，再关联 `users` 与 `classes` 得到 `user_id`、`role`、`class_id`；不采信前端传来的角色或班级。前端刷新时调用 `GET /api/me` 恢复界面身份，但它只决定显示效果，不能代替后端权限判断。

## 6. 系统登录的请求参数、响应结果与完整 HTTP 响应

请求：

```http
POST /api/login HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{"username":"teacher-a","password":"<你在.env设置的教师口令>"}
```

成功响应正文形如：

```json
{"user":{"id":1,"username":"teacher-a","displayName":"王老师","role":"teacher","classId":1,"className":"A班"}}
```

完整状态行和 Header（特别是 `Set-Cookie`、`HttpOnly`、`SameSite=Lax`）由脚本保存到 `docs/evidence/02-teacher-login-http.txt`。提交作业时截图该文件或浏览器 Network 面板的 Headers/Response 两栏；截图前应遮住 Cookie token。
