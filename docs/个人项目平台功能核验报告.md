# CampusClaw 个人项目平台功能核验报告

核验日期：2026-10-26。核验对象：本地工作树（已提交基线 `e6b6556`，含第 5 课数据层与智能体管理的未提交增量）及运行中的 Docker Compose 实例。仓库地址：<https://github.com/ariayue0525/campusclaw-traceable-retrieval>。

## 1. 项目简介与结论

CampusClaw 是 Go、React、MySQL、Qdrant 组成的班级教研材料库。教师管理材料与教学智能体；师生可在实时班级权限约束下检索材料、查看引用，并使用当前的班级问答。访问令牌采用 JWT Bearer，服务端每次读取用户实时角色和班级。

五项平台能力尚未全部达标。知识库检索已可用；多智能体和内置技能已有数据层及教师智能体 API，但尚未接入学生问答；提示词模板只有固定提示词和智能体角色提示词字段，没有模板管理与渲染；技能上传/执行、外部工具和 MCP 尚未实现。不能将表中存在技能或智能体记录等同于运行时具备相应能力。

## 2. 五项功能核验

1. **内置多个 AI 应用：部分具备。** `backend/internal/store/store.go:79-86` 为 A/B 班初始化解题助手；`backend/internal/server/agents.go:14-18` 提供智能体列表、创建、读取、修改接口，并由服务端做教师和班级校验。前端 `frontend/src/App.tsx:85-106` 仅有材料库、搜索、班级问答三个入口，学生不能在页面选择智能体；`POST /api/ask` 请求体没有 `agent_id`，回答不使用所选智能体。
2. **提示词模板：部分具备。** `backend/internal/retrieval/ask.go:139-165` 提供固定 system/user 提示词组装；`tutor_agents.prompt` 可持久化角色文本。未找到提示词模板的增删改查、变量插值或将智能体角色提示词送入现有问答链路的实现。
3. **知识库检索：具备。** `backend/internal/retrieval/service.go:179-235` 支持关键字、向量及混合检索；MySQL 和 Qdrant 均按当前班级限制，命中后回 MySQL 取正文；`backend/internal/retrieval/fuse.go:49-105` 执行 RRF 排序并生成摘录和来源。现有问答尚未用智能体材料绑定进一步缩小检索范围。
4. **内置 Skill 与上传：部分具备。** `backend/internal/store/store.go:79-86` 为每班写入“数学解题引导”技能元数据和正文，并建立智能体绑定；`skills.tools_json` 记录 `knowledge_search`。路由表 `backend/internal/server/server.go:61-77` 及 `agents.go:14-18` 未提供技能上传/编辑接口；问答不读取技能绑定，也没有技能匹配或执行。
5. **外部工具与 MCP：未具备。** 现有模型请求结构 `backend/internal/llm/chat.go:41-46` 只有 `model`、`messages`、`temperature`、`max_tokens`。服务端路由和启动链路没有 MCP 客户端、工具发现/调用或工具结果回传。技能元数据中的 `knowledge_search` 只是保存的名称。

## 3. 对话与 LLM 接口的实际链路

浏览器通过 `frontend/src/api.ts:81-83` 发送 `POST /api/ask`，JSON 为 `{"q":"本轮问题","history":[{"role":"user","content":"..."},{"role":"assistant","content":"..."}]}`，请求头带 `Authorization: Bearer <access_token>`。服务端 `backend/internal/server/server.go:197-209` 从数据库用户取得班级，丢弃 `history` 中非 user/assistant 的角色，再以该班级做混合检索。

当检索命中且网关密钥已配置，`backend/internal/llm/chat.go:59-84` 向配置的 `<LLM_GATEWAY_BASE_URL>/chat/completions` 发送一次非流式 HTTP POST：

```json
{
  "model": "<CHAT_MODEL，默认 gpt-4o-mini>",
  "messages": [
    {"role": "system", "content": "服务端固定的班级知识库约束"},
    {"role": "user", "content": "编号命中材料的标题、切片号、字符位置、摘录、客户端提供的历史与本轮问题"}
  ],
  "temperature": 0.2,
  "max_tokens": 600
}
```

HTTP 头为 `Content-Type: application/json` 和配置密钥时的 `Authorization: Bearer <gateway_key>`。system 文本要求仅依据编号资料作答并标注 `[1]` 等来源；user 文本格式由 `backend/internal/retrieval/ask.go:147-165` 固定生成。网关响应只读取 `choices[0].message.content` 并去除首尾空白；若网关返回错误、空 choices 或空正文，按 `ASK_EXTRACT_FALLBACK` 退回原文摘录或返回 503。API 成功响应包含 `answer`、`status`、`citations`、`mode`、`answer_source`。当前没有 `stream`、`tools`、`tool_choice` 或 MCP 相关字段。智能体 `prompt` 与独立提示词模板内容均不在这两个 `messages` 中。

当前容器的网关密钥为未设置状态。实测 A 班学生提问“语文教研计划”：HTTP 200，`status=ok`，`mode=hybrid`，`answer_source=extract`，引用 1 条，标题为“A班语文教研计划”，回答为该命中段落的原文摘录。此请求**没有调用 LLM**；无法据此声称已实测真实网关返回。上述网关载荷与响应解析结论来自当前代码及单元测试。

## 4. 五个问题的核验回答

1. **每轮传什么、回什么；模板是否传递？** 见第 3 节。只有命中且网关客户端存在才发请求；每次发两条消息，固定 system 和拼接后的 user。返回取第一条 choice 的正文。当前没有独立模板管理；已存的智能体角色提示词不会传递到现有 `/api/ask`。无命中时 `backend/internal/retrieval/ask.go:92-96` 返回 `no_evidence` 和空引用，不发 LLM 请求。
2. **绑定知识库后是否传全部内容？** 否。当前问答先在登录用户班级检索，默认最多选 `ASK_TOP_K=4` 条命中；每条送给模型的是最多 `SNIPPET_MAX_CHARS=240` 个正文字符附近的摘录及标题/位置，截断时另加省略号（`service.go:179-235`，`fuse.go:127-161`）。并不发送整库或整篇材料。当前 `tutor_agent_materials` 绑定尚未用于问答过滤，不能称之为“按智能体绑定知识库检索”。
3. **绑定 Skill 后是否传其全部内容？** 否。技能正文存在 `skills.source_text`，绑定存在 `tutor_agent_skills`，但 `/api/ask` 只调用 `retrieval.Ask`；该路径不读取 `skills`，也不把技能全文或片段加入模型请求。
4. **Skill 的执行逻辑？** 当前尚无执行逻辑。没有关键词路由、激活记录、技能规程拼入提示词或 `knowledge_search` 工具调度。实际执行的是固定班级 RAG：检索、RRF 融合、生成或摘录。
5. **集成 MCP 后传给 LLM 什么？** 当前未集成，故不存在可实测的 MCP 请求。现有 LLM 载荷严格只有第 3 节的四个字段，没有工具 schema、工具调用结果或 MCP 服务器信息；不能把预期设计写成当前行为。

## 5. 验证证据与限制

- `docker build --target test -t campusclaw-audit-test ./backend`：完成，后端所有包测试通过。
- `docker run --rm campusclaw-audit-test go test -count=1 -v ./internal/retrieval ./internal/llm ./internal/server`：检索 10 项、服务端 5 项通过；LLM 包目前无专门测试文件。
- `npm test -- --run`：前端 2 个测试文件、7 项通过。
- `npm run build`：TypeScript 编译与 Vite 生产构建通过。
- `python3 apitest/run_all.py`：数据库结构、登录、智能体及 A/B 班级隔离共 3 个测试场景通过，0 失败；HTML 报告保存在本机忽略目录。
- 运行中 API 容器 `/health` 返回 `{"status":"ok"}`；网关密钥未设置。单次真实 HTTP 问答返回 200、摘录和 1 条可追溯引用。
- 接口回归测试前的 MySQL 只读计数：智能体 6、技能 5、智能体技能关联 6、智能体材料关联 17、教学会话 1、消息 0。接口测试随后又创建一条测试智能体记录；这些数据包含本机历次测试生成的记录，不能视为干净环境的种子数量。认证 `sessions` 与教学 `conversations` 职责分离。
- Qdrant 容器健康标记为 `unhealthy`，但本次混合问答成功。未配置真实网关密钥，因此第三方 LLM 返回、技能上传/执行和 MCP 调用都没有实测结果。
